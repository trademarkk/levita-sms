# amoCRM → МоиЗвонки: SMS при новой заявке

Небольшая serverless-функция для Vercel без базы данных. При `leads[add]` или `leads[status]` она повторно читает сделку в amoCRM, проверяет воронку и этап, выбирает основной контакт и отправляет SMS. Для доступа к amoCRM используется долгосрочный токен внешней интеграции. Текст SMS зависит от времени поступления события по часовому поясу Краснодара (`Europe/Moscow`): с 10:00 до 21:29 включительно используется `SMS_TEXT`, с 21:30 до 09:59 — `SMS_TEXT_AFTER_HOURS`.

Отправка использует [официальный REST API «МоиЗвонки»](https://www.moizvonki.ru/guide/api/): `POST https://[домен].moizvonki.ru/api/v1`, `Content-Type: application/json`, JSON с `user_name`, `api_key`, `action: "calls.send_sms"`, `to` и `text`. HTTP 200 подтверждает выполнение метода на стороне сервиса, но фактическую доставку на телефон адресата нужно проверять отдельно.

## Настройка

1. В Vercel импортируйте GitHub-репозиторий `trademarkk/levita-sms`, создайте проект и выполните первый деплой. Получите его постоянный HTTPS-домен и проверьте, что `https://ВАШ-ДОМЕН.vercel.app/api/oauth-redirect` отвечает HTTP 200. Для этой проверки секреты ещё не нужны.
2. В amoCRM выберите **Внешняя интеграция → Создать** для этого сервиса, работающего только через API. В поле **Ссылка для перенаправления** укажите адрес из пункта 1; ссылка на хук об отключении необязательна. На вкладке **Ключи и доступы** нажмите **Сгенерировать токен**, выберите дату окончания и скопируйте долгосрочный токен. Он показывается только один раз. По [документации amoCRM](https://www.amocrm.ru/developers/content/oauth/step-by-step) долгосрочный токен доступен внешним и приватным интеграциям, действует выбранный срок от 1 дня до 5 лет и не требует refresh token. Приватная интеграция здесь не нужна; в некоторых аккаунтах её создание связано с необратимым отказом от технической поддержки по вопросам ошибок системы.
3. Перенесите переменные из `.env.example` в переменные окружения Vercel для Production и повторите деплой, чтобы они применились. Не коммитьте `.env` или `.env.local`.
4. `AMO_BASE_URL` — точный адрес аккаунта, например `https://company.amocrm.ru`. `AMO_LONG_LIVED_TOKEN` — полученный долгосрочный токен. `AMO_PIPELINE_ID` и `AMO_STATUS_ID` — числовые ID нужной воронки и этапа «Новая заявка». Название этапа для фильтрации не используется.
5. `WEBHOOK_SECRET` — длинная случайная строка. Webhook URL: `https://ВАШ-ДОМЕН.vercel.app/api/webhook?key=ВАШ-СЕКРЕТ`. Секрет в URL может попадать в журналы и историю; ограничьте доступ к ним. amoCRM не предоставляет универсальную подпись для этих CRM webhook, поэтому URL-секрет обязателен.
6. В кабинете «МоиЗвонки» найдите **Настройки → Интеграция** и API-ключ. Для заявок, у которых студия ещё неизвестна, выберите одного пользователя `userName` (email) с работающим Android-телефоном. Подключённая SIM для фактической отправки определяется настройками сервиса/телефона; если SIM несколько, проверьте её на тестовом SMS. В приложении на телефоне проверьте режим отправки **без подтверждения**. Обычный виджет amoCRM может требовать подтверждения отдельно.
7. Оставьте `STUDIO_FIELD_ID` пустым. В `STUDIO_ROUTES_JSON` используйте единственный маршрут `default`, как в `.env.example`: заполните адрес API, выбранный логин и API-ключ только в переменной окружения Vercel. Тогда все заявки на этапе «Новая заявка» отправляются через выбранного пользователя независимо от будущего распределения по студиям. Если позже понадобится маршрутизация по студиям, укажите ID поля сделки в `STUDIO_FIELD_ID` и добавьте маршруты по точным значениям поля; неизвестное значение не подставляет маршрут другой студии.
   `SMS_TEXT_AFTER_HOURS` — текст для времени вне интервала 10:00–21:29. Если переменная ещё не задана, используется безопасный стандартный текст: «LEVITA: заявку получили. Сейчас не работаем. Свяжемся после 10:00.» Для созданной сделки берётся время создания из webhook, для перехода в этап — время изменения из webhook; если его нет, используется текущее время обработки.
8. В разделе **амоМаркет → WEB HOOKS** amoCRM настройте обычный CRM webhook на нужные события по [описанию формата](https://www.amocrm.ru/developers/content/crm_platform/webhooks-format). Обработчик рассчитан на `application/x-www-form-urlencoded` данные (`leads[add]` и `leads[status]`). Если все заявки попадают на нужный этап только при смене статуса, подпишитесь лишь на **смену статуса**. Если часть сделок создаётся сразу на нём, потребуется также **добавление сделки**. Триггер Digital Pipeline «API: отправить webhook» может передавать другой формат и для этой версии проекта не используется.
9. Создайте тестовую сделку с вашим номером и проверьте SMS, отправителя и логи Vercel. Затем проверьте реальную последовательность создания заявки. Не отправляйте маркетинговые SMS без необходимого согласия адресата.

## Повторы и ошибки

Без внешнего хранилища проект не помнит предыдущие вызовы. Повторный webhook по той же сделке может отправить SMS ещё раз. Два события для одной сделки внутри одного HTTP-запроса обрабатываются один раз. После успешного ответа API статус `accepted` означает принятие запроса «МоиЗвонки», а не доставку адресату. При сетевой неопределённости статус `review_required`; перед повторным запуском проверьте журнал «МоиЗвонки» и телефон. Логи содержат ID сделки и студию, но не номер клиента, текст SMS и ключи.

## Локальная проверка

`npm test` проверяет разбор событий и номера. Для локального запроса нужен совместимый HTTP wrapper или `vercel dev` с заполненной `.env`. Реальные секреты и отправка SMS не требуются для unit-тестов.
