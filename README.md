# amoCRM → МоиЗвонки: SMS при новой заявке

Небольшая serverless-функция для Vercel без базы данных. При `leads[add]` или `leads[status]` она сразу подтверждает приём webhook, а затем в фоне читает сделку в amoCRM, проверяет воронку и этап из webhook (если он передан), выбирает основной контакт и отправляет SMS. Этап из события важен, когда сделка уже перемещена к моменту обработки. Для доступа к amoCRM используется долгосрочный токен внешней интеграции. Текст SMS зависит от времени события по часовому поясу Краснодара (`Europe/Moscow`): с 21:30 до 06:00 включительно используется `SMS_TEXT_AFTER_HOURS`, с 06:01 до 09:50 — `SMS_TEXT_MORNING`, с 09:51 до 21:29 — `SMS_TEXT`.

Отправка использует [официальный REST API «МоиЗвонки»](https://www.moizvonki.ru/guide/api/): `POST https://[домен].moizvonki.ru/api/v1`, `Content-Type: application/json`, JSON с `user_name`, `api_key`, `action: "calls.send_sms"`, `to` и `text`. HTTP 200 подтверждает выполнение метода на стороне сервиса, но фактическую доставку на телефон адресата нужно проверять отдельно.

## Настройка

1. В Vercel импортируйте GitHub-репозиторий `trademarkk/levita-sms`, создайте проект и выполните первый деплой. Получите его постоянный HTTPS-домен и проверьте, что `https://ВАШ-ДОМЕН.vercel.app/api/oauth-redirect` отвечает HTTP 200. Для этой проверки секреты ещё не нужны.
2. В amoCRM выберите **Внешняя интеграция → Создать** для этого сервиса, работающего только через API. В поле **Ссылка для перенаправления** укажите адрес из пункта 1; ссылка на хук об отключении необязательна. На вкладке **Ключи и доступы** нажмите **Сгенерировать токен**, выберите дату окончания и скопируйте долгосрочный токен. Он показывается только один раз. По [документации amoCRM](https://www.amocrm.ru/developers/content/oauth/step-by-step) долгосрочный токен доступен внешним и приватным интеграциям, действует выбранный срок от 1 дня до 5 лет и не требует refresh token. Приватная интеграция здесь не нужна; в некоторых аккаунтах её создание связано с необратимым отказом от технической поддержки по вопросам ошибок системы.
3. Перенесите переменные из `.env.example` в переменные окружения Vercel для Production и повторите деплой, чтобы они применились. Не коммитьте `.env` или `.env.local`.
4. `AMO_BASE_URL` — точный адрес аккаунта, например `https://company.amocrm.ru`. `AMO_LONG_LIVED_TOKEN` — полученный долгосрочный токен. `AMO_PIPELINE_ID` и `AMO_STATUS_ID` — числовые ID нужной воронки и этапа «Новая заявка». Название этапа для фильтрации не используется.
5. `WEBHOOK_SECRET` — длинная случайная строка. Webhook URL: `https://ВАШ-ДОМЕН.vercel.app/api/webhook?key=ВАШ-СЕКРЕТ`. Секрет в URL может попадать в журналы и историю; ограничьте доступ к ним. amoCRM не предоставляет универсальную подпись для этих CRM webhook, поэтому URL-секрет обязателен.
6. В кабинете «МоиЗвонки» найдите **Настройки → Интеграция** и API-ключ. Для заявок, у которых студия ещё неизвестна, выберите одного пользователя `userName` (email) с работающим Android-телефоном. Подключённая SIM для фактической отправки определяется настройками сервиса/телефона; если SIM несколько, проверьте её на тестовом SMS. В приложении на телефоне проверьте режим отправки **без подтверждения**. Обычный виджет amoCRM может требовать подтверждения отдельно.
7. Оставьте `STUDIO_FIELD_ID` пустым. В `STUDIO_ROUTES_JSON` используйте единственный маршрут `default`, как в `.env.example`: заполните адрес API, выбранный логин и API-ключ только в переменной окружения Vercel. Тогда все заявки на этапе «Новая заявка» отправляются через выбранного пользователя независимо от будущего распределения по студиям. Если позже понадобится маршрутизация по студиям, укажите ID поля сделки в `STUDIO_FIELD_ID` и добавьте маршруты по точным значениям поля; неизвестное значение не подставляет маршрут другой студии.
   `SMS_TEXT_MORNING` — новая обязательная переменная с текстом для 06:01–09:50. Добавьте её в Production **до публикации обновлённого кода**: если её нет, утренняя заявка завершится ошибкой без отправки SMS. `SMS_TEXT` остаётся дневным текстом для 09:51–21:29. `SMS_TEXT_AFTER_HOURS` остаётся ночным текстом для 21:30–06:00. Если ночная переменная не задана, используется прежний стандартный текст: «LEVITA: заявку получили. Сейчас не работаем. Свяжемся после 10:00.» Для созданной сделки берётся время создания из webhook, для перехода в этап — время изменения из webhook; если его нет, используется время приёма запроса перед фоновой обработкой.
8. В **Сделки → нужная воронка → Настроить воронку** добавьте на этапе **«Новая заявка»** один триггер **«API: отправить webhook»**. В поле «Выполнить» выберите **«После перехода или создания в этапе»**, укажите URL из пункта 5, оставьте условия пустыми и флажок **«Применить триггер ко всем сделкам в текущей стадии»** снятым. Нажмите **«Готово»**, затем **«Сохранить»** на странице воронки. Этот способ использует [webhook Digital Pipeline](https://www.amocrm.ru/developers/content/digital_pipeline/webhooks) с событием `leads[status]`. Обработчик принимает форму `application/x-www-form-urlencoded` с полями вида `leads[status][0][id]`. Если ранее был настроен обычный webhook в **амоМаркет → WEB HOOKS** с тем же адресом `/api/webhook`, отключите именно его после сохранения триггера. Одновременно два способа запуска использовать не нужно. Другие интеграции оставьте как есть.
9. Создайте тестовую сделку с вашим номером и проверьте SMS, отправителя и логи Vercel. Затем проверьте реальную последовательность создания заявки. Не отправляйте маркетинговые SMS без необходимого согласия адресата.

## Повторы и ошибки

amoCRM [ожидает ответ webhook не более двух секунд](https://www.amocrm.ru/developers/content/crm_platform/webhooks-format). Поэтому обработчик проверяет метод, URL-секрет и наличие событий, регистрирует фоновую работу через официальный [`waitUntil` Vercel](https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package#waituntil) и сразу возвращает HTTP 200 с `{ "received": true }`. Это подтверждает только приём события. Ожидание amoCRM API и «МоиЗвонки» не задерживает ответ. Холодный запуск самой функции всё ещё может занять больше двух секунд. Фоновая задача ограничена временем выполнения функции и не является устойчивой очередью: при остановке/таймауте задачи или ошибке чтения CRM потребуется проверить логи и повторить обработку вручную после проверки отправки.

Два события для одной сделки внутри одного HTTP-запроса обрабатываются один раз. Дополнительно одна работающая копия функции помнит попытку отправки по каждой сделке в течение часа. Запись делается **до** запроса SMS API, поэтому параллельные вызовы и сетевой сбой после передачи команды не запускают вторую отправку в той же копии. До получения контакта и корректного номера запись не создаётся. Защита хранится только в памяти: другая копия функции, перезапуск, новый деплой или истечение часа могут пропустить повтор. Это **не гарантия одной SMS** между всеми вызовами Vercel; для неё нужно общее постоянное хранилище с атомарной блокировкой. Redis не используется.

Логи:

- `webhook_received` — событие принято для фоновой обработки;
- `sms_dispatch_started` — начат один вызов SMS API;
- `sms_accepted` и итоговый `webhook_result: accepted` — результат одного и того же вызова; две строки не означают две SMS;
- `duplicate_in_instance` — повтор пропущен защитой в памяти;
- `lead_error` со `step` — ошибка до отправки;
- `review_required` — результат SMS API неизвестен/ошибка, автоматическая повторная отправка не выполняется.

`accepted` означает успешный ответ «МоиЗвонки», а не доставку адресату. При сетевой неопределённости перед повторным запуском проверьте отправляющий телефон. Логи содержат ID сделки и студию, но не номер клиента, текст SMS и ключи. Проект не добавляет сообщения в карточки amoCRM; подключённая отдельно интеграция «МоиЗвонки» может вести историю SMS самостоятельно.

## Локальная проверка

`npm test` проверяет разбор событий и номера. Для локального запроса нужен совместимый HTTP wrapper или `vercel dev` с заполненной `.env`. Реальные секреты и отправка SMS не требуются для unit-тестов.
